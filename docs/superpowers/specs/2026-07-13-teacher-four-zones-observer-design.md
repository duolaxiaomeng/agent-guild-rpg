# 教师四区观察 UI 设计

## 目标

优化教师观察原型 v3 的四个区域，让教师进入主城区后能在 3 秒内判断当前区域、需要关注的人和下一步动作。正式 Phaser 场景截图继续作为唯一世界视觉真相，原型只叠加观察层和区域交互。

## 范围

本轮只修改 `prototypes/teacher-main-city-v3`：

- 工作室大厅
- 工位区
- 协作室
- 评审区
- 顶部导航、区域 Tab、右侧观察面板和人物点击交互

本轮不修改正式 Phaser 场景、API、数据库、WebSocket、任务提交、教师裁定和授权业务。

## 统一布局

页面采用 `Teacher Observer Studio` 结构：

- 左侧约 70% 为正式场景画布，保持人物、桌子、家具和区域空间关系。
- 右侧约 30% 为教师观察面板，显示当前区域专属信息。
- 顶部保留 Day、课堂在线状态、课堂控制和返回工作台入口。
- 顶部 Tab 是唯一的区域导航，四个区域分别是大厅、工位、协作、评审。
- 画布内不增加虚线、路线编号或新的路线图例，不遮挡核心人物和家具。
- 底部只保留当前区域名称与轻量提示。

## 四区信息模型

### 工作室大厅

定位是入口与导览。观察面板显示在线人数、区域入口、公告和异常 Agent。大厅人物点击显示 NPC 的职责、当前状态和导览作用。主要操作是进入区域和查看 NPC，不在观察层发起业务写操作。

### 工位区

定位是 Agent 运行状态。观察面板显示 Agent 列表、工作状态、最近心跳、当前任务和需要关注的离线项。人物点击显示 Agent 角色、当前任务、心跳和关联任务入口。工位家具和人物继续由正式场景负责呈现。

### 协作室

定位是交接与共享记忆。观察面板显示参与 Agent、交接进度、共享记忆同步状态和待回应事项。人物或房间点击显示交接记录入口。观察层不直接创建授权、不发送消息，相关写操作跳转到已有业务页面。

### 评审区

定位是证据与裁定入口。观察面板显示待评审数量、AI 初评状态、证据完整度和风险提示。点击评审对象后显示摘要和教师评审入口。观察层不直接执行裁定，教师通过已有评审工作台完成业务写操作。

## 交互规则

1. 点击区域 Tab 时切换正式场景底图、当前区域标题、可点击人物和侧栏内容。
2. 点击人物时更新右侧面板，不使用弹窗，不改变画布尺寸。
3. 区域切换后清除旧人物详情，避免跨区显示过期信息。
4. 观察层按钮统一标记为只读或跳转入口，不能伪装成已执行的业务动作。
5. 实时数据不可用时显示明确的“实时数据暂不可用”空态，不使用静态在线数据冒充后端真相。
6. 保持窄屏下场景在上、侧栏在下的顺序；不让侧栏挤压或裁切正式场景。

## 视觉规则

- 沿用当前深色教师工作台外壳，与正式 Phaser 的像素场景形成明确层级。
- 观察面板使用冷蓝作为结构色，绿色表示在线/已同步，琥珀色表示待处理，红色表示风险或离线。
- 四区使用不同的标题、摘要字段和行动入口，避免只替换区域名称。
- 场景截图统一按正式版本的 16:9 比例展示，禁止旧版 `1280×900` 裁切策略。

## 数据边界

原型阶段使用可替换的观察读模型，字段命名对齐现有业务概念：`zone`、`status`、`currentTask`、`heartbeat`、`participants`、`memorySync`、`reviewQueue`。不扩展后端契约；后续接真实 API 时由页面层替换读模型，展示组件不自行推导业务真相。

## 验收

- 四个 Tab 均能切换到底图和对应侧栏。
- 每个区域至少有一组独有的信息字段和行动入口。
- 大厅、工位区人物点击能打开正确详情；协作室、评审区能展示区域状态空态或入口。
- 画布无虚线、箭头、路线编号和旧版路线图例。
- 1440px 桌面宽度下场景与侧栏均可见；窄屏下不发生横向溢出。
- v3 原型可通过静态 HTTP 服务启动，并完成四区切换与点击 smoke 验证。
