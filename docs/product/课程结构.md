# 课程结构

## 总览

- 总时长：10天（两周工作日）
- 每天上午 8:30-11:00 教学（两节课 × 60分钟，中间30分钟休息）
- 下午 + 晚上：学生自主实践（按当天三档目标推进）
- 讲师：全程（Day 1-10）由李老师主讲，配 2 名带薪学生助教
- 课程首要标准：有趣 + 学会（见 `课程核心理念.md` 总纲）

## 每日结构原则（2026-06-12 定稿）

每天 = **一条主线 + 三档完成标准 + 当天产出**。

| 档位 | 作用 | 面向谁 |
|---|---|---|
| 保底目标 | 当天必须完成，不完成就算掉队 | 零基础、小学生、工具不熟的人 |
| 标准目标 | 大部分学生应该完成 | 普通学生 |
| 挑战目标 | 提前完成的人继续深入 | 熟练学生、队长、职场人 |

**关键原则：三档必须围绕同一个产出升级，不能变成三个不同任务**——否则就是三套课，老师和助教无法控场。

这样设计的好处：零基础不被压垮、熟练学生不空转、全班在同一条主线上不散、助教能快速判断谁掉队、每天都有可验收产出。

## 课程主线叙事

**主线**：学生在构建项目的过程中，学会用 Agent 完整地把一个系统从 0 做到落地。
**终点**：将系统接入 Agent World，上线公网。

Agent 是工具和团队，系统是被构建的东西，学生是在成长的人。每一天的教学都服务于这条主线——学生遇到什么问题，就学解决这个问题的方法，然后立刻用回自己的项目。

## 工具决策（已定）

开课前确定 Agent 工具方案并提前通知学生（候选已收敛为 Codex / Claude Code，学生自备账号）。**Day 1 Session 1 即进行环境配置**，报名后向学生发放课前预装指引。

## 差异化机制

- **三档目标**：见每日结构原则——差异化的主载体
- **互助组织**：结对/公会制（机制细节见 `课程游戏化设计.md`，L2 挂接时定稿）
- **巡视辅导**：李老师 + 2 名助教在下午/晚上流动辅导

## Week 1（Day 1-3）· Agent 认知 + 熟练 + 构想启动

> **报名前置 SOP**：接入 Agent World 是报名条件，学生 Day 1 前已完成注册 + 按指引完成工具预装。
> **立项思考三步走**：Day 1 = 发散方向，Day 2 = 收敛到 1-2 个，Day 3 = 确认立项
> **成长线**：Day 1 = 第一次指挥 Agent，Day 2 = 会指挥，Day 3 = 系统第一次存在

---

### Day 1 · 主线：工具跑通 + 第一次成功指挥 Agent

**上午教学**
- Session 1：开场即确定互助分组（有经验带零基础）→ 手把手配置 Agent 工具环境（Codex 或 Claude Code，Mac + Windows 同步进行；学生已按预装指引装好，课上以排错收尾为主）
- Session 2：当场探索 Agent World → "你发现了什么？什么问题还没被解决？" → Agent 是什么；**Vibe Seeking vs Vibe Coding**：实践的价值在于成长，不在于让 AI 帮你做完

**三档目标（围绕"第一次成功指挥 Agent"升级）**

- 保底：
  - 成功打开 Codex / Claude Code
  - 进入一个项目目录
  - 让 Agent 读取并解释一个文件
  - 写下一句话：Agent 刚才帮我做了什么
- 标准：
  - 让 Agent 创建或修改一个简单文件
  - 能说清楚 Agent 做了哪几步
  - 探索 Agent World，找到 3 个有意思的系统
  - 写下自己的 3 个项目方向（发散，不求想清）【补：Day 2 收敛依赖此项】
- 挑战：
  - 让 Agent 读 AGENTS.md 或类似规则文件，并解释"它为什么会按这个规则工作"
  - 帮队友解决一个环境问题
  - 总结一份"我第一次指挥 Agent 的经验".

**当天产出**：跑通的环境 + 第一次指挥记录（+ 3 个方向）

**配套脚手架（Day 1 随发，专堵零基础卡点；不进课堂教学）**
- 预装指引已为每人**预建好项目目录**——打开工具就在里面，不必自己从零创建（"进入项目目录"是零基础第一个小时最易卡死的地方）
- **新手速查卡**：怎么存档不丢工作、什么时候开新对话/什么时候接着聊、Demo 的三种常见形态
- 开场一句话**点破安全认知**：Agent 的操作是真实的（会改你的文件、会跑命令、动手前会请你确认）——它不是聊天，所以放心用、也别乱授权

**→ 为 Day 2 埋伏笔**：工具在手、指挥过一次，但还不会"有效"指挥

---

### Day 2 · 主线：从会用到会指挥

**上午教学**
- Session 1：Vibe Seeking 四步练习法——**先写预期 → 问 Agent → 对比预期和实际 → 解释为什么有差距**；"解释差距"是成长发生的地方；**再补一步闭环——修正：带着差距去追问/纠正 Agent 重做，直到接近预期**（发现错 ≠ 会改对，修正才是"指挥"的核心动作）；现场用自己的环境实战一轮
- Session 2：从观察到构想——Agent World 里缺什么？**你的系统要存在于这个世界里，它解决什么问题？** 引导立项思考

**三档目标（围绕"一次有预期的指挥"升级）**

- 保底：
  - 用"目标 → 预期 → 执行 → 对比"完成一个小任务
  - 必须先写预期，再问 Agent
  - 发现结果不对时，至少修正一次，让它更接近预期
- 标准：
  - 对同一个任务迭代两轮
  - 写出"预期和实际哪里不一样，为什么不一样"
  - 把 Day 1 的 3 个项目方向收敛到 1-2 个
- 挑战：
  - 给自己的项目方向写 3 条验收标准
  - 拆解一个优秀 Agent World 系统：它给谁用、输入是什么、输出是什么、边界是什么
  - 帮队友改一条模糊指令，让它变成清楚指令

**当天产出**：一份四步法任务记录 + 收敛后的 1-2 个方向

**→ 为 Day 3 埋伏笔**：会指挥了、方向收敛了，明天让系统第一次存在

---

### Day 3 · 主线：立项确认 + 粗糙 Demo

**上午教学**
- Session 1：真实案例演示——拿到一个项目 → 分析需求 → 用 Agent 构建完善；重点：如何思考、如何拆解、如何判断输出（Vibe Seeking 的真实样子）
- Session 2："你刚刚看到的，就是你接下来要做的。现在来确认你的系统是什么。" → 立项书确认——做什么、为谁做、**Agent 的角色类型**（Agent 就是产品本身 / Agent 辅助产品 / Agent 协调多模块）、Agent 创造了什么不可替代的价值
- **动手前 5 分钟**：Demo 的三种常见形态范例（对话机器人 / 网页 / 命令行脚本）+ **最小可行切片法**——别想整个系统，先选一种形态、先让最核心的一个动作跑起来（堵住"我不知道我要做的东西长什么样"这个 Day 3 最大卡点）

**三档目标（围绕"立项 + 最小 Demo"升级）**

- 保底：
  - 确认一个项目方向
  - 写清楚：做什么、给谁用、解决什么问题
  - 用 Agent 做出一个能展示的最小 Demo：先选一种形态（对话/网页/脚本），先让最核心的一个动作跑起来，哪怕很粗糙
- 标准：
  - Demo 跑通一个完整核心流程
  - 写清楚 Agent 在系统里的角色
  - 能向队友演示 3 分钟
- 挑战：
  - 给 Demo 写 3 个测试场景
  - 让另一个同学试用并记录反馈
  - 初步写出系统边界：哪些事情 Agent 做、哪些事情普通逻辑做、哪些事情暂时不做

**当天产出**：立项书 + 粗糙 Demo

**→ 为 Day 4 埋伏笔**：系统第一次存在了，但它是混乱的，需要设计思维来整理

---

## Week 2（Day 4-10）· 设计 + 构建 + 发散完善 + 上线

> ⚠️ **Day 4-10 为按新结构转换的草拟稿（Claude 草拟，待李老师逐日审定）；Day 1-3 已由李老师定稿。**
> **核心链条**：上午用方法解决昨天的问题 → 下午/晚上按三档推进 → 第二天解决新问题
> **学习主线**：Day 4 = 学会设计，Day 5 = 学会构建，Day 6-9 = 学会迭代，Day 10 = 学会交付

---

### Day 4 · 主线：用设计思维把 Demo 整理清楚（草拟待审）

**上午教学**
- Session 1：开场 10 分钟全班分享昨晚暴露的问题（边界不清、谁负责什么）→ DDD：你的系统的边界在哪里，谁负责什么；SDD：模块之间怎么对话，接口怎么定义
- Session 2：Agent 规则定制（它该做什么、不该做什么、用什么方式回应）→ TDD（写验证用例：给定这个输入，应该输出什么）；全程用学生自己的 Demo 举例（人话先行，课尾才给学名）

**三档目标（围绕"自己系统的设计三件套"升级）**

- 保底：
  - 画出自己系统的边界图：哪些 Agent 做、哪些普通逻辑做、哪些不做
  - 给系统写 3 条 Agent 规则
  - 用 Agent 按其中一条规则改进 Demo
- 标准：
  - 完成设计三件套：领域模型 + 接口规范 + Agent 规则
  - 按设计精化 Demo（在地基上补结构，不是推倒重来）
  - 主流程试跑一遍
- 挑战：
  - 写出 3 个验收用例（输入 → 应有输出）
  - 请队友评审三件套，记录 2 条修改意见
  - 把一条 Agent 规则改到"另一个人看了就能照做"的清晰度

**当天产出**：设计三件套 + 按设计精化的 Demo

**→ 为 Day 5 埋伏笔**：有了设计，主流程还没完全跑通

---

### Day 5 · 主线：0→1 完成——核心流程端到端跑通（草拟待审）

**上午教学**
- Session 1：如何有效指挥 Agent——把设计文档转化为可执行指令；指令失效时先判断是设计问题还是表达问题
- Session 2：0→1 完成标准——**核心流程端到端跑通 + 能向陌生人演示 + 没有让系统崩溃的严重 bug**；如何对照验收用例验收

**三档目标（围绕"达到完成标准的系统"升级）**

- 保底：
  - 核心流程从头到尾自己操作跑通一次
  - 对照完成标准三条逐项自检，记下没达到的
- 标准：
  - 达到完成标准（端到端 + 可演示 + 无致命 bug）
  - 向队友完整演示一遍
- 挑战：
  - 用 Day 4 的验收用例逐条验收并修复不通过项
  - 给系统写一个自动化验收脚本
  - 帮一个还没跑通的队友定位问题

**当天产出**：达到完成标准的 0→1 系统

**→ 为 Day 6 埋伏笔**：跑通了，现在让它变得更好——好不好，用户说了算

---

### Day 6 · 主线：第一轮迭代——从真实反馈里找问题、定优先级（草拟待审）

**上午教学**
- Session 1：1→100 的发现框架——用户视角（别人用会卡在哪）、边界情况（极端输入会怎样）、机会视角（它还能做什么现在做不到的）
- Session 2：优先级排序——哪些是缺陷要修、哪些是机会值得扩展；Vibe Seeking 在迭代中：先判断根本原因，不是哪里不好就让 Agent 改哪

**三档目标（围绕"一轮有据可依的迭代"升级）**

- 保底：
  - 从收到的使用反馈里挑出 1 个最关键缺陷，修掉
  - 记录：改之前什么样、改之后什么样
- 标准：
  - 列出迭代清单：缺陷/机会分类、排好优先级
  - 完成 2-3 个关键项的修复或改进
  - 探索 1 个新方向并记录是否有价值
- 挑战：
  - 扩展一项系统能力（如接入一个新工具），并验证扩展后真的更好
  - 用数据说话：对比迭代前后别人使用你系统的反馈差异

**当天产出**：迭代清单 + 第一轮迭代后的系统

**→ 为 Day 7 埋伏笔**：修了能看见的问题，但系统还能更强

---

### Day 7 · 主线：深化核心能力 + 你的系统第一次被 Agent 调用（草拟待审）

**上午教学**
- Session 1：能力深化 vs 能力扩展——什么时候让系统做更多，什么时候让它做得更精
- Session 2：从"人用"到"Agent 用"——另一个 Agent 怎么理解你的系统；能力边界重审：功能变多后，原来的规则和接口还合适吗

**三档目标（围绕"更强的系统 + 首次被 Agent 调用"升级）**

- 保底：
  - 完成 1 项核心能力的深化（同一件事做得更准或更稳）
  - 更新能力说明书：现在能做什么、不能做什么
- 标准：
  - 让自己的 Agent 成功调用一个同学的系统，记录调用体验
  - 根据被调用的反馈调整自己系统的接口或说明
- 挑战：
  - 和一个同学完成双系统联动：你的 Agent 调用他的系统完成一个组合任务
  - 重审并修订自己的规则与接口（功能增长后的一致性检查）

**当天产出**：深化后的系统 + 更新的能力说明书 + 首次 Agent 间调用记录

**→ 为 Day 8 埋伏笔**：自己觉得强了，盲点只有别人能看见

---

### Day 8 · 主线：盲点发现——真实用户当面用你的系统（草拟待审）

**上午教学**
- Session 1：发散思维——从使用场景出发还有哪些没想到的用法；**直播使用环节预告与规则：原作者只能看不能说**
- Session 2：完善策略——用观察更新迭代计划，区分"必须做"和"可以做"

**三档目标（围绕"盲点清单与修复"升级）**

- 保底：
  - 完整观摩自己的系统被同学当面使用，记下 3 个盲点（卡在哪、误解了什么）
  - 修掉其中最痛的 1 个
- 标准：
  - 修复主要盲点，更新迭代计划（必须做 / 可以做）
  - 能力说明书做最后一次完整更新
- 挑战：
  - 以 Agent 调用方身份测 2 个同学的系统，提交接口体验报告
  - 把一个盲点的修复做成对比演示（修复前 vs 修复后）

**当天产出**：盲点清单 + 三轮迭代后的成熟系统

**→ 为 Day 9 埋伏笔**：系统成熟了，准备让世界读懂它

---

### Day 9 · 主线：准备上线——让另一个 Agent 第一次读就能用你的系统（草拟待审）

**上午教学**
- Session 1：能力说明书的最终写法（输入、输出、适合谁、不能做什么、使用场景举例）；机器可读：另一个 Agent 怎么发现并调用你；接入 Agent World 流程预演
- Session 2：演示结构训练——5 分钟讲清楚：解决什么问题、Agent 的角色、一个真实场景 live demo、一个关键结果；彩排

**三档目标（围绕"接入就绪"升级）**

- 保底：
  - 能力说明书完成（输入/输出/适合谁/不能做什么/场景举例）
  - 跟着接入指引把流程预演一遍
- 标准：
  - 说明书做成机器可读格式
  - 自检：立项书、设计文档、能力说明书三者一致
  - 完成 5 分钟演示彩排
- 挑战：
  - 系统被 3 个同学的 Agent 成功调用（提前达成上线条件）
  - 给队友的演示当观众并提 2 条改进意见

**当天产出**：接入就绪包（机器可读说明书 + 一致性自检 + 彩排过的演示）

**→ 为 Day 10 埋伏笔**：一切就绪，明天进入世界

---

### Day 10 · 主线：进入世界——挂载 Agent World + 公开 Demo Day（草拟待审）

> **这是系统正式诞生的那一天。** 有外部观众，是真正的产品发布，不只是班内总结。
**上午**
- Session 1：正式提交 Agent World，完成接入；同学的 Agent 实测调用，验证接入质量
- Session 2：**公开 Demo Day**——面向外部观众的演示（40 人规模的形式见 `班级构成与教学注意事项.md`：博览会/摊位制）

**三档目标（围绕"上线 + 公开演示"升级）**

- 保底：
  - 完成挂载，系统上线
  - 完成自己的公开演示
- 标准：
  - 系统被同学的 Agent 现场成功调用
  - 收集至少 2 条外部观众反馈
- 挑战：
  - 现场帮 1 个同学完成接入
  - 给自己的系统写课后维护计划（工具订阅、迭代方向）

**当天产出**：上线公网的系统 + 一场公开演示

**下午/晚上**
- 接入完成后系统上线公网，正式在 Agent World 中存在
- 课程结束，系统的生命周期刚开始
