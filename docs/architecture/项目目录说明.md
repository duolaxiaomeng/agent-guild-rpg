# 项目目录说明

本仓库采用 pnpm monorepo。源码按运行职责分层，文档和截图按交付用途分层；不要为了“看起来整齐”跨层移动源码入口。

## 源码层

```text
game-system-two/
├── apps/
│   ├── web/                # 前端：Next.js、React、Phaser、页面、组件、E2E
│   ├── api/                # 后端：NestJS、Prisma、REST、WebSocket、队列
│   └── agent-connector/    # 本机 Agent：配对、心跳、事件、受限命令执行
├── packages/
│   └── contracts/          # 共享层：Zod schema、契约测试、推导类型
├── scripts/                # 工具层：数据库、E2E、截图、双账号验证
└── docs/
    ├── product/            # 产品层：课程结构、PRD
    ├── architecture/       # 架构层：功能图、技术栈、目录说明
    ├── guides/             # 使用层：本地运行和产品使用说明
    ├── screenshots/        # 使用说明引用的固定配图
    └── superpowers/        # 设计规格与实施计划历史
```

## 产物层

```text
artifacts/
└── screenshots/
    ├── visual-regression/  # 页面、场景、角色和路线的历史验收图
    └── world/              # 当前世界场景截图和截图脚本输出
```

`artifacts/` 不被 Web、API 或 Connector 作为运行时资产读取。真正的 Phaser 资产必须放在 `apps/web/public/`，共享契约必须放在 `packages/contracts/src/`。

## 程序员定位规则

| 需求 | 首先查看 |
|---|---|
| 页面、表单、客户端状态 | `apps/web/src/app`、`apps/web/src/components` |
| 像素地图、角色、家具、HUD | `apps/web/src/components/world`、`apps/web/public/world` |
| API、权限、业务规则 | `apps/api/src/modules` |
| 数据库、seed、迁移底座 | `apps/api/prisma` |
| Agent 战队、调度、记忆 | `apps/api/src/modules/agent-*`、`apps/api/src/modules/memory` |
| 本机 Agent 执行 | `apps/agent-connector/src` |
| 前后端输入输出契约 | `packages/contracts/src` |
| 单元/集成/E2E 测试 | 各 workspace 的 `test`、`src/**/*.test.*`、`apps/web/tests/e2e` |
| 本地启动、数据库、截图 | `package.json`、`scripts/` |
| 产品需求和技术方案 | `docs/product`、`docs/architecture`、`docs/superpowers` |

## 不移动的边界

- 不移动 `apps/web`、`apps/api`、`apps/agent-connector` 和 `packages/contracts` 的 workspace 根目录。
- 不移动 `apps/web/public`、`apps/api/prisma`、各 workspace 的 `package.json`、`tsconfig`、Vitest/Playwright 配置。
- 不把截图、构建输出或调试产物放入 `apps/web/public`；只有运行时需要的资源才进入 `public`。
- 不删除历史计划、PRD、截图或数据库文件；整理只改变归档位置和引用路径。
